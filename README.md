# 모아 · 나의 투자 기록

개인 투자용 웹앱입니다. PC와 휴대폰 화면을 지원하며 React, FastAPI, SQLite로 구성합니다. 첨부된 투자관리 엑셀 구조에 맞춰 개발했습니다.

## Windows에서 간단히 시작하기

**명령어를 입력하지 않아도 됩니다.**

1. [Windows용 ZIP v1.1 내려받기](https://github.com/roy546123/my-project/raw/refs/heads/codex/moa-invest-app-20261016/releases/Moa-Windows-v1.1.zip)를 누릅니다. GitHub 로그인이 필요할 수 있습니다. 저장소의 `releases` 폴더에도 ZIP 파일이 있습니다.
2. 내려받은 ZIP을 마우스 오른쪽 버튼으로 누르고 **모두 압축 풀기**를 선택합니다.
3. 압축을 푼 폴더 안의 **`모아 시작.bat`**을 더블클릭합니다. 처음에는 구성요소를 준비하므로 인터넷 연결이 필요하고 몇 분이 걸릴 수 있습니다.
4. 자동으로 열린 모아에서 **데이터 가져오기**를 눌러 기존 투자관리 엑셀을 가져옵니다.

다음부터는 같은 파일만 더블클릭하면 됩니다. v1.1부터는 서버와 화면 파일의 실제 응답을 확인한 뒤 브라우저를 열며, 준비 창이 닫혀도 서버가 계속 실행됩니다. 종료는 **`모아 종료.bat`**, 연결 오류 확인은 **`모아 연결 확인.bat`**을 사용합니다. 자세한 안내는 [처음 읽어주세요.txt](./처음%20읽어주세요.txt)에 있습니다.

업데이트할 때는 이전 실행 창과 브라우저 탭을 닫고 새 ZIP을 **새 폴더**에 모두 압축 풀기 해 주세요. 자산 데이터는 같은 사용자 데이터 폴더에 유지됩니다. 진단 파일 `connection-check.txt`에는 자산 금액·종목명을 포함하지 않습니다. 백그라운드 서버의 종료는 실행할 때 생성한 로컬 세션 키로만 허용하며 다른 프로세스를 강제 종료하지 않습니다.

Windows 10/11 64비트용입니다. 화면과 OCR 파일을 포함하므로 Node.js·Tesseract를 설치할 필요가 없습니다. 호환되는 Python이 없으면 공식 python.org의 설치 파일을 SHA256와 Windows 서명으로 검증한 뒤 사용자 계정에 설치합니다. 전용 구성요소와 데이터는 `%LOCALAPPDATA%\MoaInvest`에 저장합니다. 원본 엑셀이나 자산 DB는 다운로드에 포함하지 않으며 최초 한 번 가져와야 합니다.

현재 검증 환경은 Linux입니다. 브라우저 OCR과 동일한 데스크톱 서버 시작·재실행·데이터 보존 흐름을 검증하며, Windows 설치 화면과 설치 프로그램 실행은 실제 Windows PC에서 추가 확인이 필요합니다.

## 주요 기능

- **대시보드**: 보유자산 평가금액·원금·평가손익, 날짜별 추이, 계좌별 비중.
- **보유 자산**: 증권·ISA·IRP·연금·퇴직연금 통합 목록, 검색·필터, 원화 평가금액·수량 수정, 자산 추가.
- **DCA**: 종목별 하루 계획금액, 실제 체결 확인 후 일괄 기록, 직접 매수 입력, 월별 기록. 동일 계획/날짜 중복 저장을 차단합니다.
- **자산 기록**: 날짜별 총 원금·평가금액·메모 저장/수정/삭제. 원금 증감을 제외한 시장 손익 계산.
- **엑셀 이전**: 미리보기 → 명시적 확인 → 저장. 기존 데이터를 교체할 때 자동 DB 백업.
- **스크린샷**: 내 컴퓨터에서 한국어/영어 OCR → 종목·원화 총액·수량 검토 → 저장. Windows 간편 실행은 브라우저 OCR을 사용하며 외부 인식 API나 API 키가 필요 없습니다.
- **내보내기**: 엑셀 내보내기와 전체 SQLite 백업 다운로드, 백업 복원 CLI.

## 개발 환경에서 직접 설치하기

Python 3.12+, Node.js 22.12+, Tesseract 5가 필요합니다. Ubuntu는 `sudo apt-get install tesseract-ocr`, macOS는 `brew install tesseract`로 OCR 엔진을 준비합니다. 아래 명령은 Bash 기준입니다.

```bash
cd /workspace/my-project
bash scripts/setup.sh
npm start
```

`npm start`는 8000번 포트의 로컬 서버를 실행합니다. 브라우저 주소창에 `127.0.0.1:8000`을 입력합니다. `PORT=8001 npm start`로 포트를 바꿀 수 있습니다. 개인용이며 로그인 기능은 없으므로 인터넷에 직접 공개하지 마세요. 외부 접속이 필요하면 인증과 HTTPS를 먼저 구성해야 합니다.

클라우드 안에서 실행한 서버는 본인 PC의 `127.0.0.1`과 다릅니다. 클라우드 접속에는 해당 서비스가 제공하는 접속 기능이 필요합니다. 내려받은 소스의 `index.html`을 파일로 직접 열거나 `dist`만 정적 호스팅하면 서버가 연결되지 않습니다. `npm start`로 전체 앱을 실행하세요. 시작할 때 화면을 다시 빌드하며, 화면 파일·서버 연결 실패 시 재시도 안내를 표시합니다. 역방향 프록시로 `/portfolio/` 같은 하위 경로에 연결하는 경우에는 접두 경로를 제거하여 앱 서버로 전달하고 경로 끝의 `/`를 유지합니다.

이 클라우드 작업 환경에는 전달받은 엑셀의 **보유자산 22개, 일별 기록 107개, DCA 계획 8개**를 이미 가져왔습니다. 개인정보는 `.data/`에 저장하며 Git에 포함하지 않습니다. 새로 코드를 받으면 빈 앱으로 시작합니다. 앱의 **데이터 가져오기**에서 엑셀을 선택하거나 다음 명령을 사용하세요.

```bash
.venv/bin/python scripts/import_excel.py '/path/to/투자관리.xlsx'
```

기존 데이터를 교체하려면 화면의 교체 확인을 사용하거나 CLI에 `--replace`를 명시합니다. 기존 보유종목·매수기록·자산기록·DCA 계획을 모두 엑셀 기준으로 바꾸며, 먼저 `.data/backups/`에 백업합니다.

## 매일 사용하는 순서

1. **DCA 매수 기록**에서 날짜를 선택하고 실제 체결된 종목·원화 금액을 확인해 일괄 저장합니다. 계획금액 자체는 실제 체결을 뜻하지 않습니다. 미국 휴장일을 자동 판정하거나 주문하지 않습니다.
2. 캡처를 사용한다면 **데이터 가져오기 → 스크린샷 인식**에서 업로드합니다. 계좌·종목·날짜·총 체결금액을 확인해 저장합니다. 영문 ETF 티커를 후보로 구분하며, 달러 단가를 원화 체결총액으로 임의 변환하지 않습니다. 인식하지 못한 값은 직접 입력합니다. 활성 DCA 계획과 종목·계좌가 일치하는 스크린샷 매수는 해당 계획에 연결해 중복을 막습니다.
3. **보유 자산**에서 증권사에 표시된 최신 평가금액을 원화로 갱신합니다. 매수는 그 금액만큼 원금과 평가금액에 더하므로 매수만으로 손익이 생기지 않습니다. 실제 수량을 입력하지 않았다면 보유 수량은 ‘알 수 없음’으로 처리합니다.
4. **자산 변동 기록 → 자산 기록 추가**에서 그날의 총 원금·평가금액을 저장합니다. 보유종목을 수정하거나 매수기록을 저장하는 것만으로 과거 날짜별 기록이 바뀌지는 않습니다. 같은 날짜는 명시적으로 확인해야 덮어씁니다.

한국 증권앱 관례에 따라 수익은 빨강, 손실은 파랑으로 표시합니다. 모든 합산 금액은 원화입니다. ‘시장 손익’은 원본 엑셀과 같은 계산 방식입니다.

```text
평가손익 = 평가금액 − 투자원금
시장 손익 = 이번 평가금액 − 직전 평가금액 − (이번 원금 − 직전 원금)
시장 수익률 = 시장 손익 ÷ 직전 평가금액
```

원금 변동을 조정한 간단한 지표이며, 배당·세금·매도 실현손익·입출금 시점을 반영한 TWR/IRR은 아닙니다. 첫 기록에는 비교 대상이 없으므로 시장 손익을 표시하지 않습니다. 이틀 이상 간격의 기록은 해당 기간 변동입니다.

## 엑셀과 OCR의 범위

`보유종목(입력)`의 개별 종목 행만 가져오고 합계행은 제외합니다. `일별 수익률`은 실제 평가금액이 저장된 날짜만 가져오며 빈 서식행은 제외합니다. `매일 N만원` 보유종목 메모에서 DCA 계획을 구성합니다. 수식은 실행하거나 재계산하지 않고 엑셀에 저장된 계산 결과만 읽습니다.

`집행기록`은 보유자산에 이미 반영되어 있을 수 있어 중복 매수로 이전하지 않습니다. MDD 전략, 실현손익, 퇴직연금·절세계좌의 미래 납입계획 시트도 이번 버전의 가져오기 대상이 아닙니다. 내보낸 엑셀은 보유자산·일별 기록을 다시 가져올 수 있지만 **거래·계획·내부 ID의 완전한 복원은 SQLite 백업을 사용**해야 합니다.

스크린샷은 최대 10MB, 2,000만 화소 이하의 PNG/JPG/WEBP입니다. Windows 간편 실행에서는 브라우저 안에서 이미지를 인식하고, 서버 OCR 모드에서는 임시 파일로 처리한 뒤 삭제합니다. 인식한 문자는 화면 검토용으로만 사용하며 승인한 매수 항목만 DB에 저장합니다. 증권사별 레이아웃 전체를 검증한 것은 아니므로 총액·통화·계좌를 반드시 확인해야 합니다.

실시간 주가·환율·증권사 연동, 자동 주문, 매도·실현손익 회계는 아직 지원하지 않습니다.

## 데이터 보관과 복원

- 개발 환경의 `.data/portfolio.sqlite3`, Windows 간편 실행의 `%LOCALAPPDATA%\MoaInvest\data\portfolio.sqlite3`: 실제 자산과 거래. 각 데이터 폴더의 `backups/`: 자동·수동 DB 백업.
- `.data/`, 원본, DB, 캡처는 Git에 넣지 않습니다. 서버가 꺼져도 DB는 남지만, 작업환경 자체가 삭제되면 함께 사라질 수 있으므로 별도 백업을 내려받으세요.
- 왼쪽 **데이터 백업**을 누르면 전체 DB를 다운로드합니다. 엑셀은 **엑셀 내보내기**를 사용합니다.
- 복원할 때는 먼저 서버를 종료한 뒤 실행합니다. 복원 전의 현재 DB도 자동 백업합니다.

```bash
.venv/bin/python scripts/restore.py '/path/to/portfolio-backup.sqlite3'
npm start
```

잘못 입력한 매수는 이후 수정이 없는 해당 종목의 최신 매수부터 취소할 수 있습니다. 평가금액을 직접 수정한 뒤에는 자동 되돌리기로 최신 값을 훼손하지 않도록 취소를 차단합니다. 이 경우 보유자산에서 금액을 정정하고 메모로 남겨 주세요.

## 개발·검증

```bash
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m unittest discover -s tests -v
npm run build
npm run test:e2e
```

브라우저 테스트는 `/usr/bin/chromium`을 사용합니다. 다른 경로는 `CHROMIUM_PATH`로 지정합니다. 테스트 전용 임시 DB와 8011번 포트를 사용하여 실제 자산을 변경하지 않습니다. API 테스트도 임시 DB에서 계산, 원자적 저장, 중복 방지, 미리보기/백업, 취소, 엑셀 왕복, OCR 파싱을 검증합니다.

개발 중에는 한 터미널에서 `.venv/bin/python -m uvicorn backend.app:app --reload --port 8000`, 다른 터미널에서 `npm run dev`를 실행합니다. Vite의 `/api` 프록시가 서버에 연결됩니다. 각 클라우드 작업은 이미 격리되어 있으므로 기존 체크아웃을 그대로 사용하며 별도 Git worktree를 만들 필요가 없습니다.

화면을 수정한 뒤 Windows 다운로드를 갱신할 때는 `npm run build:desktop`과 `python scripts/package_windows.py`를 실행하고 `desktop/`과 `releases/`의 ZIP도 커밋합니다. 사용자 DB를 포함하지 않고 화면·OCR·검증용 해시 목록·실행 파일만 생성합니다. OCR은 Tesseract 명령이 있으면 서버에서 처리하고, 없으면 동봉한 Tesseract.js로 브라우저에서 처리합니다.
